## 六、各类用户的证书恢复

### 现状问题

```
之前只设计了根证书持有者的恢复（短码/证书加密/Worker）。
普通管理员和上网用户丢失证书后没有任何恢复路径 ❌
```

### 分级恢复策略

```
丢失证书 → 根据用户角色走不同流程:

┌──────────────────────────────────────────────────────────────┐
│  根管理员丢失                                                    │
│  → /recover 页面（短码 / 证书加密 / Worker）                   │
│  → 自服务，无需他人审批                                        │
│  → 已实现 ✅                                                   │
├──────────────────────────────────────────────────────────────┤
│  普通管理员丢失                                                   │
│  → 重新提交 /signup 申请                                       │
│  → 管理员在 /manager 审批                                       │
│  → 但: 如何证明你是你？（没有根证书，第一次申请时的证书也没了）      │
│  → 方案: 引入"恢复联系码"概念                                    │
│     • 首次获批时系统生成 6 位联系码（admin 可见）                │
│     • 联系码存在权限表里（SHA256 哈希）                          │
│     • 重新申请时输入联系码 → 验证通过 → 自动批准恢复            │
│  → 如果联系码也丢了 → 联系根管理员手动批准                       │
├──────────────────────────────────────────────────────────────┤
│  上网用户丢失                                                    │
│  → 最简单: 重新提交 /signup 申请                                 │
│  → 管理员在 /manager 重新批准（和第一次一样）                     │
│  → 建议: 记住自己设备的 hostname（申请时填的）                    │
│  → 如果 hostname 也忘了 → 联系管理员                             │
├──────────────────────────────────────────────────────────────┤
│  MCU 设备丢失证书                                                 │
│  → 重新烧录固件（固件里包含新的证书）                              │
│  → 或者通过串口/网络上传新证书                                    │
│  → 管理员在 /manager 重新批准                                     │
└──────────────────────────────────────────────────────────────┘
```

### 恢复联系码（普通管理员专用）

```
概念:
  管理员首次获批时，系统自动生成 6 位"联系码"
  联系码 = 随机 6 位数字 + 字母混合（类似短恢复码）
  仅存储 SHA256(联系码) 在权限表中

使用:
  管理员访问 /recover/admin
  输入: 用户名(hostname) + 联系码
  系统验证 SHA256 匹配 → 允许重新提交证书
  自动批准新证书（跳过人工审批步骤）

安全:
  联系码是管理员与系统之间的"恢复秘密"
  泄露风险: 管理员自己有责任保管
  如果泄露: 根管理员可以吊销旧码签发新码

  联系码与短恢复码的区别:
    短恢复码: 根管理员专用，8位，可恢复任意证书
    联系码:   普通管理员专用，6位，仅恢复自己的证书
```

### /recover 页面扩展

```
/recover          → 根管理员恢复（短码/证书加密/Worker）
/recover/admin    → 普通管理员恢复（联系码）
/recover/device   → 重新申请（普通用户，无特殊通道）

未登录状态下可见:
  /recover          — 始终可见
  /recover/admin    — 始终可见  
  /recover/device   — 跳转到 /signup
```
